= Visualization Architecture: Regime-Aware Phase Response Mapping
:sectnums:
:toc: left

This document defines the architectural principles for the `go-regexp-re` performance dashboard. It establishes the "Regime-Aware Phase Response Mapping" model, focusing on discrete execution transitions in the SBL space.

== Philosophy: Structural Transition Visibility

Performance in `go-regexp-re` is not a continuous surface but a collection of **Discrete Performance Regimes**. Our visualization must prioritize the visibility of these transitions over aesthetic smoothness.

Key objectives:
1.  **Identify Phase Transitions**: Clearly mark where strategy shifts (e.g., MAP $\to$ DFA).
2.  **Characterize the S-Dependency**: Visualize how Speedup is inversely proportional to Selectivity ($S$).
3.  **Map the Overhead Floor**: Explicitly identify regions where constant overheads (DFA lookup or CGO) become dominant.

== The SBL Coordinate System

|===
| Axis | Definition | Physical Significance

| **Selectivity (S)**
| $S = \text{MatchCount} / \text{InputSize}$
| The primary driver of Speedup. Determines MAP efficiency.

| **Complexity (B)**
| $\text{round}(B, 2)$ (Quantized)
| Determines DFA state-space pressure and transition latency.

| **Locality (L)**
| Hybrid predictability metric.
| Determines SWAR/SIMD skip efficiency (Regime: Warp).
|===

== Visualization Model: Regional Phase Mapping

=== 1. Primary Projection (S-Speedup Plane)
* **X-Axis**: Selectivity ($S$), on a reversed $[1.0, 0.0]$ scale.
* **Y-Axis**: Speedup Factor (Relative vs. `GoRegexp`) on a **Logarithmic Scale** ($10^{-2}$ to $10^6$).
* **Baseline Invariant**: The standard library is a static horizontal line at $Y=1.0$.

=== 2. Performance Zones (Shading)
To provide instant analytical context, the plot area is divided into three functional zones:

1.  **Efficiency Frontier (Gold Shading)**: The region where Speedup $> 10\times$. This represents the "Peak Competitive Zone" where MAP and Warp optimizations are fully leveraged.
2.  **Standard Parity (Clear/Neutral)**: The region between $0.8\times$ and $1.5\times$. Indicates typical DFA execution parity with the standard library.
3.  **Overhead Zone (Red/Gray Shading)**: The region below $Y=1.0$. Explicitly labels the "DFA/CGO Overhead Zone" to visualize the physical floor of our performance.

=== 3. Threshold Markers
* **MAP Transition Boundary**: A vertical dashed line marking the $S$-coordinate where MAP speedup falls below a significant threshold (typically $2.0\times$). This marks the "Regime Shift" from pre-filter to core DFA.

== Competitive Frontier (Multi-Engine Analysis)

The system visualizes the **Competitive Envelope**:
- **Envelope Line**: A polyline representing the *maximum speedup* achieved by any competing engine (PCRE2, RE2, Hyperscan) at each S-coordinate.
- **Superiority Gap**: The vertical distance between `GoRegexpRe` points and the Envelope Line, proving our architectural advantage in specific SBL slices.

== Interaction and Tiered Data

* **Tier 1 (Landscape JSON)**: Global SBL coordinates and throughput metrics.
* **Tier 2 (Trace JSON)**: Lazy-loaded `Regexp.Explain()` data and per-pass execution costs.
